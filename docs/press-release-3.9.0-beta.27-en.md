# PolicyWatcher Beta 27 connects public policy evidence with operational publication readiness

**The release adds a deterministic administrative action centre, a five-stage publication-readiness funnel, role-specific evidence views and privacy-minimised measurement while preserving the platform’s existing public-evidence gates.**

**ROME, 1 August 2026**  -  PolicyWatcher has published version 3.9.0 Beta 27, “Admin Operational Readiness”, a release focused on how administrators and auditors inspect the operational conditions behind public policy-change evidence.

PolicyWatcher is an independent civic-tech project created by Fabrizio Degni. It monitors a configured inventory of public technology-policy sources and presents source status, observed changes, evidence links and analytical limitations through public interfaces. The project is designed to make a published observation easier to inspect, cite and correct. It does not provide legal advice, compliance certification or exhaustive market coverage.

Beta 27 reorganises the protected administrative dashboard around a single evidence sequence: priorities, publication readiness, live status, role-safe action and bounded measurement. Its Operational Action Center returns no more than five deterministic priorities. Each returned record includes severity, cause, evidence timestamp, affected records, stated impact and one destination in the responsible console.

The new Publication Readiness Funnel describes five separate stages: Configured, Retrieved, Baseline verified, Public and Analysed. It keeps numerators, a shared denominator and excluded records visible. A scan that has not run, a missing metric or an unavailable protected endpoint is represented as unavailable rather than being converted into a zero or a healthy state.

Independent status cards retrieve bounded evidence for Dataset QA, Database Readiness, Webhook Delivery and VPS services. Administrative users are directed to operational controls; auditors receive read-only verification routes over the same evidence. Server-side authorisation remains unchanged. Responsive layouts, keyboard focus handoff, live refresh feedback and text alternatives for risk charts are included as implementation features, not as an accessibility certification.

The release also introduces privacy-minimised dashboard measurement. Four allowlisted event types can record bounded operational interactions with server-derived roles, per-visit deduplication, minimum-sample disclosure and a 90-day retention boundary. The telemetry excludes IP addresses, user agents, referrers, email addresses, account identifiers, query strings, free text and arbitrary metadata. These events do not prove that an operational task was completed or resolved.

The current configured product inventory comprises 16 companies across six sectors and excludes a WAZE administrative onboarding fixture. The analytical framework defines 15 canonical KPIs across privacy, AI governance and ethics. These figures describe configured product scope and method. They do not establish complete public coverage, adoption, performance or measured compliance. Unavailable assessments are displayed as “Not assessed” and have no numerical value.

Publicly accessible PolicyWatcher resources include a server-rendered Knowledge layer, a dated release archive, the Claim Registry, methodology pages, a structured Data Room, reviewed Pulse story leads, deterministic Story Packs, reusable citation formats and an evidence-oriented Press Kit. The Chrome extension is published in the Chrome Web Store; an Edge listing has not been verified and Safari availability is not claimed.

“The purpose of this release is to make missing operational evidence visible before it can be mistaken for a positive state,” said Fabrizio Degni, creator of PolicyWatcher. “A status, score or public record should retain its source, timestamp and limitation when it is inspected or reused.”

Beta 27 is available at [policywatcher.online](https://policywatcher.online).
