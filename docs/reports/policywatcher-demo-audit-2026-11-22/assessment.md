## Actionable findings and gates

1. **Blocking qualification gate  -  independent completeness is not supplied by contracts.** Four offline counterexamples pass. Enhance a reviewed reference inventory with critical clause occurrences, table structures and linked annex scope. Do not infer the ground truth from the extractor output itself. Preserve holds until source-specific evidence exists. Source: `scripts/engine-completeness-falsifiers.ts`, `src/lib/engine/document.ts:126`.
2. **Blocking qualification gate  -  complete live semantic workflow is not demonstrated.** Historical O2 records report analyst success but unavailable verifiers; six false claims passed structural checks, so no semantic accuracy percentage can be computed from those trials. Free-tier verification quota was observed at20/day in that dated trial; that is not a current account guarantee and cannot cover500 changed documents/day. New measurements need the real current quota, change prevalence, retries and backlog. Source: `docs/reports/engine-v6-o2-wave2-2026-11-09.md`.
3. **Blocking capacity gate  -  intended hosted worker workload differs from SSH diagnostics.** Earlier367/500 target-host extractions and a later4/133 recovery subset cannot be combined into a contemporaneous500 score. Hosted worker intentionally allows one live task across processes; preview batches are capped50. Measure full500 distinct policies with scheduled work, models, retry/backoff, database contention, publication gates disabled and explicit success/hold counts. Source: `src/lib/engine/store.ts:34,144`, `src/lib/engine/hostedWorker.ts:184`.
4. **P2 design risk  -  full task payload repeatedly polled.** `/api/admin/engine` includes every task for each of20 latest runs and is polled every5 seconds. This is currently small (24 tasks in the observed private database), but run history at500 scopes can create increasingly large payloads and repeated DB work. Return run aggregates in status, paginate task detail on expansion, avoid overlapping polls and measure latency/payload at realistic history. This is not a demonstrated production incident. Source: `src/app/api/admin/engine/route.ts:36-44`, `src/app/admin/engine/page.tsx:67-72`.
5. **P2 design risk  -  no engine-artifact retention/GC procedure found.** Each content-addressed artifact is capped12MB and read back with hash/byte integrity. Total storage, legal retention policy, reachability protection for published evidence, backup horizon and cleanup rehearsal are not provided by that per-object limit. Define and test a referenced-artifact retention policy before daily scale. Do not delete evidence during this audit. Source: `src/lib/engine/store.ts:234-245`, Prisma `EngineArtifact` model.
6. **Operational prerequisite  -  readiness does not equal companion management.** Production renderer responds ready, but VPS Operations Agent is not configured. Existing renderer can be demonstrated as observed; automatic remote upgrade/rollback controls should be shown unavailable unless separately connected and tested. No service configuration was changed.
7. **Confirmed operational prerequisite  -  private renderer/model configuration.** The fresh post-restoration read at03:04UTC verifies absent renderer URL/secret, Gemini key and explicit analyst/verifier IDs; one contract for113policies; no baselines/snapshots/claims/outbox; three saved completed observe/silent runs. Restored r3 is currently an acquisition/review workspace: rendered fallback and real analyst/verifier inference cannot be demonstrated with its present configuration. App-based model reviews do not supply these runtime credentials or quota entitlements.
