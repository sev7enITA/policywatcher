## Adjudication of the three HTML expectation failures

The original report is retained unchanged, including the failed expectations. Do not convert 8/11 into a general extraction-accuracy score.

1. **Integral external annex: substantiated completeness gap.** The parent states that a linked retention PDF is integral. The extracted text retains the label but not the URL or annex content. The raw HTML retains the link, so it is recoverable evidence, not irreversible loss. The parent receives `contract_satisfied`; this cannot establish completeness of the composite policy. A reviewed dependency manifest and actual annex capture/validation are needed before approving that scope.
2. **Row-spanning table: original hold expectation too strong as a defect claim.** r3 retains `[colspan=1; rowspan=2]` rather than expanding a rectangular grid. We did not prove information loss. The output still needs a semantic association test on the actual model path. No parser change is justified by this fixture alone.
3. **Unlinked `hidden` clause: no missing-text defect reproduced.** The full exception survives extraction. The HTML visibility attribute alone does not prove whether the text belongs to the operative policy. The hold expectation represents unresolved scope/visibility policy, not evidence of silent omission. A rendered reference and reviewed source scope are required for a real document.

## Gemini and GLM review, with disagreements retained

New reviews were obtained using Gemini 4 Argon High in Vivaldi and GLM-5.3 Max in ZCode through existing access. These are advisory reviews, not pipeline SDK inference. GLM inspected local code read-only; it ran no tests, database writes or live scans. Raw review extracts are in the evidence directory; the full UI receipts remain in `output/o2-20261107`.

Accepted themes: exact citation matching does not establish entailment; bilingual equivalence needs review; source-specific extraction results do not generalize; candidate identities and every held source remain in the denominator; PDF provenance and structure need explicit qualification.

Corrections and rejected claims:

- Gemini asserted that paid API access is mandatory and that free quotas necessarily fail 500/day. This was **not measured**, conflicts with the free-only constraint and ignores the workload mix: unchanged documents need not invoke both models. Required evidence is actual free entitlement and observed quota/throughput, not purchase.
- Both reviews miscounted the historical corpus in parts of their answers. It contains **one complete control plus six incomplete variants**, four accepted. The receipts take precedence.
- Gemini supplied example offsets and custom verdict names that are not r3's actual schema. We used offsets computed from frozen documents and actual `validateClaims`/`validateVerification`, not the suggested numbers or invented verdict codes.
- GLM's claim that text outside table cells disappears was falsified by a direct reproduction: the HTML parser relocates that text and extraction preserves it.
- GLM's PDF concern is supported for the archived decoded AWS sample and the current paragraph-only converter. It is a qualification mismatch, not an observed unsafe publication: the source is held. It does not mean the historical transport-observation campaign was a semantic qualification.
- GLM identified a potential ledger gap when a publish transaction fails. Static ordering supports further investigation, but this campaign did not reproduce that fault and r3 remains observe/silent. The analysis remains in the checkpoint; claiming evidence was destroyed would be wrong.
- GLM's proposed fixed “60-block” output ceiling was not measured. Token and diff budgets are explicit limits; injecting MAX_TOKENS tests error handling, not the largest real supported document.
- The stable extractor's legacy `5.2.0` label is a provenance limitation already disclosed in O1. Product release `5.5.0` and exact implementation hashes remain separate identities; no relabeling of old evidence occurred.

## Why the real 500/day gate has not run

The intended hosted catalogue currently has 113 policy rows and one contract, and its deployment configuration lacks the dual-model runtime setup. Complete composite-source references and a reviewed semantic corpus are also missing. Running another 500-endpoint download experiment would not satisfy the requested full pipeline test. The earlier 342 extractions out of 500 candidate endpoints on a Mac remain acquisition-only evidence.

The next live step needs an existing, demonstrably free Google API project with two accessible distinct model identities. The owner was asked only whether that access already exists, never for keys in chat or a paid upgrade. If unavailable, browser-assisted review can continue but cannot qualify the current SDK path. OpenRouter browser/connector results cannot silently substitute for r3's Google SDK; a provider adapter would be a new implementation candidate.

Before a daily capacity trial: establish the declared 500-policy catalogue and dependency scope, independently review references, measure supported/unsupported/uncertain outcomes on true positive and negative changes with live model receipts, then run the daily workload on the intended host with all 500 accounted for. No arbitrary success percentage, extrapolated requests/second or synthetic observation date is an acceptance substitute.
